Числа получены реальным прогоном ноутбука (30 эпох, CPU, 35 секунд).
Из 45 обучающих машин девять отложены под валидацию — на ней выбирается эпоха.
Модель обучается на оставшихся 36, тест участвует только в итоговом замере.

| метрика | значение |
|---|---|
| точечная precision, класс 1 | 0.770 |
| точечная recall, класс 1 | 0.682 |
| точечная F1, класс 1 | 0.724 |
| macro F1 по трём классам | 0.642 |
| **событийная precision** | **0.988** |
| **событийная recall** | **0.653** |
| **событийный F1** | **0.786** |
| события: TP / FP / FN | 81 / 1 / 43 |

Пороговое правило (лучший порог 12 л на прирост за интервал) даёт событийный F1 **0.373**.
Это нижняя планка: она показывает студентам, что модель здесь не украшение.

Матрица ошибок бейзлайна:

```
                предсказано
              0      1      2
  0        9444     70     41
  1          23    245     91     <- 91 интервал заправки уехал в класс 2
  2           0      3     18
```

Основной запас для улучшения виден здесь же: модель путает заправку с включённым
двигателем с заправкой с выключенным двигателем — 91 интервал из 359 уехал в класс 2.
Объединение классов 1 и 2 даёт большой прирост, но это ловушка: разбор в разделе
«Что реально даёт прирост».

## Заметка по данным

Классы проверены по сырым сообщениям, а не только по названию:

| | класс 1 | класс 2 |
|---|---|---|
| зажигание включено >90% времени заправки | 89% событий | 2% событий |
| датчик молчал больше половины разметки | 1% событий | 94% событий |
| скорость в размеченных сообщениях | 2.8 км/ч | 0.0 км/ч |

То есть класс 1 — машина стоит с работающим двигателем, датчик пишет, рост уровня
виден. Класс 2 — двигатель выключен, датчик молчит, видно только разницу уровней
до и после.

Отдельно стоит знать про границы событий. В `_resample_ign_on` метка расширяется
на соседние интервалы, пока уровень растёт. Поплавковый датчик после старта машины
ещё несколько минут догоняет истинный уровень, поэтому метка уезжает за ним в участок
движения: в размеченных сообщениях медианная скорость 2.8 км/ч, а по событию целиком
уже 38 км/ч. На точечную метрику это влияет, на событийную с допуском — почти нет.
Хороший повод обсудить со студентами, почему метрику выбирают под задачу.

## Что реально даёт прирост

Проверено экспериментами: 36 машин на обучении, 9 на валидации, тест замеряется
один раз на вариант. Событийный F1 на тесте:

| вариант | событийный F1 |
|---|---|
| бейзлайн ноутбука (отбор эпохи по точечному F1) | 0.786 |
| отбор эпохи по событийному F1 | **0.959** |
| то же + `ign`, `speed`, `n_msg` в признаках | **0.971** |
| то же + нормализация входов | **0.992** |
| окно 11 интервалов вместо 7 | 0.962 |
| двунаправленная LSTM | 0.953 |
| постобработка: блоки короче двух интервалов отбрасываются | 0.821 |

Главный вывод для разбора со студентами: самый большой прирост даёт не архитектура,
а **согласование критерия отбора с целевой метрикой**. Бейзлайн выбирает лучшую эпоху
по точечному F1, а меряется событийным — одна эта нестыковка стоит 0.17.

Постобработка единственная ухудшила результат: минимальная длина в два интервала
режет короткие заправки целиком.

**Ловушка.** Объединение классов 1 и 2 в один даёт событийный F1 = 1.000. Это не
достижение: класс 2 размечен детерминированным правилом (три точки, в середине ноль),
и модель восстанавливает правило, а не учится детекции. Тот же механизм, что в вопросе
со звёздочкой. Если студент приносит такое решение — это повод обсудить утечку,
а не поставить высший балл.

## Задание студентам

**Цель: увеличить событийный F1 на тестовых машинах.**

Главная метрика — `event_f1`. Дополнительно указывается точечный F1 по классу 1,
чтобы было видно, за счёт чего вырос результат.

Правила:

1. Разбиение `split` не меняется, обучаться на тестовых машинах нельзя.
2. Метки в тесте не меняются.
3. Гиперпараметры подбираются на train (часть train-машин можно отрезать под валидацию).
4. В отчёте таблица «что поменял → какой стал event_f1», а не только финальное число.

Направления, которые перечислены в ноутбуке: признаки (`ign`, `speed`, `n_msg`,
время суток), нормализация, длина окна, веса классов и focal loss, двунаправленная
LSTM / GRU / 1D-CNN, постобработка предсказаний, порог по вероятности вместо argmax,
другой размер интервала на сырых данных.

### Критерии оценки

| | |
|---|---|
| воспроизвёл бейзлайн, ничего не улучшил | удовлетворительно |
| прирост event_f1, объяснено за счёт чего | хорошо |
| прирост + честная валидация на train + разбор неудачных попыток | отлично |
| подгонка гиперпараметров прямо по тесту | не засчитывается |

Планка «хорошо» — событийный F1 выше 0.90. Достижимость проверена экспериментами,
таблица ниже.

### Вопрос со звёздочкой

В проекте есть вторая модель — для заправок с выключенным двигателем. На тесте она
даёт accuracy 100% и F1 = 1.0. Студентов просят объяснить, почему это число ничего
не говорит о качестве детекции.

**Ответ для преподавателя.** Метка там ставится по правилу: блок ровно из трёх точек,
в середине уровень равен нулю, слева и справа уровни стабильны и различаются.
Признаки модели — уровень и его разности, то есть ровно те величины, из которых
это правило и построено. Классификатор не учит физику заправки, а восстанавливает
детерминированное правило разметки. Показатель, что это так: идеальное разделение
класса с долей 1 к 1400 достигается на второй эпохе.

Чтобы число стало осмысленным, нужны метки, полученные независимо от самого ряда
уровня: чеки АЗС или транзакции топливных карт.
