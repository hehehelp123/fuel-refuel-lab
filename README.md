Числа получены реальным прогоном ноутбука (30 эпох, CPU, 45 секунд):

|---|---|
| точечная precision, класс 1 | 0.753 |
| точечная recall, класс 1 | 0.747 |
| точечная F1, класс 1 | 0.750 |
| macro F1 по трём классам | 0.661 |
| **событийная precision** | **1.000** |
| **событийная recall** | **0.744** |
| **событийный F1** | **0.853** |
| события: TP / FP / FN | 96 / 0 / 33 |

Пороговое правило (лучший порог 12 л на прирост за интервал) даёт событийный F1 **0.373**.
Это нижняя планка: она показывает студентам, что модель здесь не украшение.

Матрица ошибок бейзлайна:

```
                предсказано
              0      1      2
  0        9439     84     32
  1          19    268     72     <- 72 заправки на ходу уехали в класс 2
  2           0      4     17
```

Основной запас для улучшения виден здесь же: модель путает заправку на ходу
с заправкой на стоянке (72 интервала). Если студент объединит классы 1 и 2 в один
«была заправка», прирост он получит почти сразу. Засчитывать это стоит с оговоркой,
что при таком объединении меняется постановка задачи.

## Задание студентам

**Цель: увеличить событийный F1 на тестовых машинах.**

Главная метрика — `event_f1`. Дополнительно указывается точечный F1 по классу 1,
чтобы было видно, за счёт чего вырос результат.

Правила:

1. Разбиение `split` не меняется, обучаться на тестовых машинах нельзя.
2. Метки в тесте не меняются.
3. Гиперпараметры подбираются на train (часть train-машин можно отрезать под валидацию).
4. В отчёте таблица «что поменял → какой стал event_f1», а не только финальное число.

Направления, которые перечислены в ноутбуке: признаки (`ign`, `speed`, `n_msg`,
время суток), нормализация, длина окна, веса классов и focal loss, двунаправленная
LSTM / GRU / 1D-CNN, постобработка предсказаний, порог по вероятности вместо argmax,
другой размер интервала на сырых данных.

### Критерии оценки

| | |
|---|---|
| воспроизвёл бейзлайн, ничего не улучшил | удовлетворительно |
| прирост event_f1, объяснено за счёт чего | хорошо |
| прирост + честная валидация на train + разбор неудачных попыток | отлично |
| подгонка гиперпараметров прямо по тесту | не засчитывается |

Планка «хорошо» — событийный F1 выше 0.88. Это достижимо: пропущено 33 события,
и часть из них модель относит к классу 2.

### Вопрос со звёздочкой

В проекте есть вторая модель — для заправок при заглушенном двигателе. На тесте она
даёт accuracy 100% и F1 = 1.0. Студентов просят объяснить, почему это число ничего
не говорит о качестве детекции.

**Ответ для преподавателя.** Метка там ставится по правилу: блок ровно из трёх точек,
в середине уровень равен нулю, слева и справа уровни стабильны и различаются.
Признаки модели — уровень и его разности, то есть ровно те величины, из которых
это правило и построено. Классификатор не учит физику заправки, а восстанавливает
детерминированное правило разметки. Показатель, что это так: идеальное разделение
класса с долей 1 к 1400 достигается на второй эпохе.

Чтобы число стало осмысленным, нужны метки, полученные независимо от самого ряда
уровня: чеки АЗС или транзакции топливных карт.
